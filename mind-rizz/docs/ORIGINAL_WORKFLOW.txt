# 63. TIE HANDLING

If:

```text
Team A = 270
Team B = 270
```

System needs a tie-break rule.

Recommended configurable rule:

```text
1. Higher total score
2. Higher Level 3 score
3. Higher Level 2 score
4. Higher Level 1 score
5. If still tied → Admin resolves
```

Admin should be able to configure this later.

# 83. RLS SECURITY

Supabase Row Level Security should enforce the rules.

For example:

```text
Student A
```

must not be able to query:

```text
Student B's private information
```

even by manually changing an ID in the browser.

Admin permissions should be checked from trusted server-side logic/RLS, not merely by hiding buttons.

             │                └── Content
             │

## The key principle

**Student side = participate in the event.**

**Admin side = control the event and the entire website.**

**Public side = view the event and register.**

**Supabase = authentication + database + storage + security.**

**Next.js = website + dashboards + admin panel.**

**Vercel = deployment.**

This gives you a complete **registration → team → QR → check-in → levels → scores → ranking → results** system, while the Admin Panel also works as a **full CMS for the website**.
